- Step 1 — Attendance in the DB (migration `phase7_attendance`, no screen): `attendance_sessions` = a lesson on a date, created on first save, with a SNAPSHOT (year, class, subject, teacher, start / end) filled by a trigger from the lesson — the caller gives only lesson + date; refused: not the lesson's weekday (`attendance_wrong_day`), outside its year (`attendance_outside_year`), future (`attendance_future`); snapshot locked (`attendance_session_locked`); one per lesson + date; `taken_at/by` + `updated_at/by`. Deleting a lesson keeps its sessions (`lesson_id` → NULL, `on delete set null (lesson_id)`). `attendance_marks` = absent / late only (present = no row); late minutes optional 1–240, none for absent; note ≤ 200; student must be enrolled in the session's class that year (23514 `attendance_student_not_in_class`); session / student / school of a mark locked (`attendance_mark_locked`); deleting a student deletes their marks; a class or subject with history cannot be deleted (`setup.errors.classHasAttendance / subjectHasAttendance`). `private.school_today()` = `(now() at time zone 'Africa/Casablanca')::date` — Postgres has current tz data (UTC+0), Node does not: never compute "today" for attendance in Node. Permissions `attendance.view` + `attendance.manage` (director, surveillant only); every policy checks `has_module('attendance')`. Writes: manage any day ≤ today, only manage deletes sessions; a teacher only sessions with `teacher_id = me` and `session_date = school_today()`. Reads: view / manage all; a teacher their own sessions + their marks; a parent their children's marks + those sessions (`private.is_guardian_of_student`, `is_guardian_of_session`, `is_session_teacher(_today)` — DEFINER helpers so sessions and marks policies never read each other). `save_attendance(lesson, date, marks jsonb)` (INVOKER): creates or touches the session, then marks = exactly the list (left out = present; an unchanged mark keeps marked_by / at), all or nothing. Tests: `phase7-attendance.mjs`. **Lessons are Monday–Saturday: on Sundays the teacher same-day checks are SKIPPED** (`skip()` in `checks.mjs`, printed, never counted as passed); they were verified on Sunday 2026-10-18 in a rolled-back transaction (a `DO` block that overrides `private.school_today()`, sets `role` + `request.jwt.claims` with `set_config(…, true)`, runs the calls, then raises its results as an exception so everything rolls back). Fixture school A keeps the 2026-2027 year from `phase4.mjs` and years never overlap: the suite reuses the year containing today, adds its own days / 21:00 slots and removes only what it added.
