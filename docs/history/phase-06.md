**Done**
- Step 1 — Lessons (migration `phase6_lessons`, no screen yet): `lessons` = year + time slot + class + subject + teacher + optional room. The DB refuses: breaks (`slot_kind` is always 'lesson' and part of the FK to `time_slots (id, school_id, academic_year_id, kind)`, so a slot with lessons cannot become a break either), class / teacher / room twice on one slot (unique keys, **DEFERRABLE INITIALLY IMMEDIATE**), a teacher who does not teach the subject (FK `(teacher_id, subject_id)` → `teacher_subjects`), anything of another school or year (composite FKs). Slots of a year+day never overlap, so same slot = same time. All lesson FKs are NO ACTION: a subject, room, time slot or teacher account used by lessons cannot be deleted; removing a teacher's subject or changing their role is refused while they have lessons of it. Deleting a class deletes its lessons. Permissions (timetable module): `timetable.view` (director, surveillant, accountant, transport manager), `timetable.manage` (director, surveillant); every policy also checks `has_module('timetable')`. Reads: view/manage, a teacher their own lessons, a parent the classes their children are enrolled in (`private.is_guardian_of_class`). `swap_lessons(a, b)` (SECURITY INVOKER) defers the keys and swaps two lessons' slots in one transaction, all or nothing. `timetable_teachers(year)` (SECURITY DEFINER, advisor warning accepted on purpose) returns only id + full name + active: every teacher of the school for timetable staff, otherwise the teachers of the lessons the caller can read; profiles stay closed (no email / phone). `timetable.manage` may read `teacher_subjects`. `is_linked_to_student`: + a teacher with a lesson of the CURRENT year in the student's class that year. Error keys: `setup.errors.subjectHasLessons/roomHasLessons/slotHasLessons`, `teachers.errors.subjectHasLessons`, `staff.errors.teacherHasLessons`. Tests: `phase6-lessons.mjs`, `actions-lesson-blocks.mjs`.
- Step 2 — Class timetable (`/timetable`, no migration; nav item for `timetable.view`): `?year=` + `?class=` (current year, first class by default). Week grid = one row per distinct time range, one column per school day (`week-layout.ts`); breaks shown, never clickable; a day without a slot at that time = muted cell. Phones (< md): one card per day. `timetable.manage`: click an empty lesson cell → dialog (subject → only the teachers who teach it, auto-picked if only one → optional room; teachers / rooms busy at that slot marked "occupé : 1AC-B"); click a lesson → change subject / teacher / room or delete (the cell stays; moving = step 4). Actions `createLesson` / `updateLesson` / `deleteLesson` (`src/lib/timetable/lesson-actions.ts`, session + RLS) check first and return `{ error, field, conflict: { kind, name, className, day, start, end } }`, so the message says who is busy with which class when (`timetable.errors.teacherBusy/roomBusy/classBusy`; names wrapped with `isolate()` = FSI…PDI, times with `ltr()`); DB key violations (two people at once) map to `slotTaken/teacherBusyNow/roomBusyNow`. Teacher names come from `timetable_teachers()`. Weekly hours = sum of the class's lesson slot lengths, total + per subject (`hours.ts`, message `timetable.duration`). French messages avoid "le Lundi" (day names are capitalised): "… à ce moment : Lundi, 08:00–09:00". École Test B now has the typical Moroccan week (Mon–Fri full days, Sat morning) in 2026-2027. Tests: `actions-lessons.mjs`.
- Step 3 — Teacher and room grids (no migration): `/timetable?view=class|teacher|room` (+ `&class=` / `&teacher=` / `&room=`; the year select keeps the view). Tabs Classe / Enseignant / Salle (`view-controls.tsx`; the `TIMETABLE_VIEWS` constant lives in `src/lib/timetable/views.ts` — a constant exported from a "use client" file reaches server components as a client reference, not its value). A cell shows the subject, then the other two of class / teacher / room (`LessonCard details`). Weekly hours of the selected teacher / room (total + per subject); teacher view adds "Volume horaire des enseignants" (every teacher: classes, hours; a name opens their week). No teacher / no room → empty state with a link (`/teachers`, `/setup/rooms`). Interrupted test run? remove its fixtures (schools `rls-test-*-<run>`, users `rls-test+<run>-*`) like `removeFixtures`.
- Step 4 — Move / swap (no migration): desktop grid, any view, `timetable.manage`: drag a lesson (native HTML5 DnD) onto a free cell = move, onto another lesson of that week = swap. While dragging, EVERY cell says first whether it can take it (`planDrop()` in `src/lib/timetable/moves.ts`, from the year's lessons): "Déplacer ici" / "Échanger avec X" / red "Enseignant occupé : 1AC-B" (keys `timetable.move.classBusy|teacherBusy|roomBusy` = same names as `timetable.errors`, `conflictErrorKey()`); a refusing cell does not accept the drop and the line under the grid gives the full sentence. Toast with **Annuler** (move back / swap again). Keyboard + phones: "Déplacer" button in the lesson dialog → `MoveLessonDialog` (every slot of the week grouped by day; a slot where the lesson's CLASS has a lesson = swap; busy slots listed but disabled). Actions `moveLesson` / `swapLessons` (`move-actions.ts`, session + RLS) re-check with the shared `checkBooking()` (moved to `lesson-checks.ts`, server-only — an exported helper in a "use server" file would become a callable action); a swap checks BOTH lessons at the other's slot, then calls `swap_lessons()`. Audit `lesson.move` / `lesson.swap`. Tests: `actions-lesson-moves.mjs`. Browser test of DnD: CDP `Input.setInterceptDrags` + `Input.dispatchDragEvent`.
